# Adrobot

Обёртка над Admin API трекера Keitaro. Делает две вещи:

1. Создание кампании. По названию, списку стран и офферу создаёт кампанию с доменом, группой и источником и два потока: трафик из выбранных стран уходит редиректом на google.com, остальной идёт на оффер.
2. Редактор офферов. Загружает потоки существующей кампании и позволяет добавлять, убирать и возвращать офферы, менять и закреплять доли. Изменения копятся как черновик и уходят в Keitaro только по кнопке «Push to Keitaro».

Кроме этого, кампанию можно переименовать, включить, выключить и удалить, а поток включить, выключить, перезагрузить из Keitaro и удалить.

Бэкенд: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL, httpx. Фронтенд: Vite, React 19, TypeScript, Tailwind, shadcn/ui, TanStack Query, react-hook-form и zod.

## Запуск

Нужны Docker, [uv](https://docs.astral.sh/uv/), Node.js 24+ и pnpm.

```bash
# 1. База (PostgreSQL на порту 5433)
docker compose up -d

# 2. Бэкенд
cd backend
cp .env.example .env        # и вписать KEITARO_URL и KEITARO_API_KEY
uv sync
uv run alembic upgrade head
uv run fastapi dev app/main.py   # http://localhost:8000, документация на /docs

# 3. Фронтенд, в другом терминале
cd frontend
pnpm install
pnpm dev                    # http://localhost:5180
```

Vite проксирует `/api` на `localhost:8000`, так что CORS не нужен.

Порт базы 5433, а не 5432, чтобы не мешать локальному PostgreSQL. Если 5432 у вас свободен, поменяйте порт в `docker-compose.yml` и `DATABASE_URL`.

### Переменные `.env`

| Переменная | Что это |
|---|---|
| `DATABASE_URL` | строка подключения SQLAlchemy, по умолчанию база из `docker-compose.yml` |
| `KEITARO_URL` | адрес трекера без `/admin_api/v1`, например `https://keitaro.example.com` |
| `KEITARO_API_KEY` | ключ Admin API, уходит в заголовке `Api-Key` |

Домены, группы и источники трафика не зашиты в конфиг: форма создания берёт их из Keitaro.

### Миграции

```bash
cd backend
uv run alembic upgrade head                              # накатить
uv run alembic revision --autogenerate -m "описание"     # новая миграция после правки моделей
uv run alembic downgrade -1                              # откатить последнюю
```

### Тесты и проверки

```bash
cd backend && uv run pytest && uv run ruff check .
cd frontend && pnpm typecheck && pnpm lint && pnpm format:check
```

Тесты не ходят в Keitaro: вместо него подставляется `FakeKeitaro` из `tests/conftest.py`, который отвечает так же, как тестовый стенд. База в тестах — SQLite в памяти.

Хуки ставятся через [pre-commit](https://pre-commit.com/): `uvx pre-commit install` (типы хуков заданы в конфиге). Они запускают ruff, pytest, tsc, oxlint и oxfmt и проверяют, что сообщение коммита в формате Conventional Commits.

## Структура

```
backend/app/
  keitaro.py          клиент Admin API, по методу на каждый маршрут
  offers.py           каталог офферов с кешем и поиском (в Keitaro поиска нет)
  campaigns/          создание кампании
  editor/
    models.py         Campaign, Stream, StreamOffer
    weights.py        пересчёт долей
    service.py        логика редактора, без commit
    router.py         HTTP-ручки, commit здесь
frontend/src/
  pages/              список кампаний, создание, редактор
  components/         выбор оффера, диалог подтверждения, компоненты shadcn
  lib/api.ts          типы и запросы к бэкенду
```

Сервисы меняют сессию, но не коммитят. Ручка коммитит один раз в конце, поэтому если на середине Keitaro вернул ошибку, в базе не остаётся половины изменений.

## Как работают черновики

Keitaro хранит потоки и офферы, а наша база хранит копию и черновик поверх неё. У каждого оффера в потоке два набора полей:

- `share` и `state` — то, что видит и правит пользователь;
- `published_share` и `published_state` — то, что сейчас в Keitaro. Для оффера, добавленного у нас и ещё не отправленного, они пустые.

Оффер считается черновиком, если эти наборы различаются, а поток — если в нём есть хоть один такой оффер. Такой поток подсвечивается жёлтым.

- Push отправляет активные офферы в `PUT /streams/{id}`. Keitaro заменяет список целиком, поэтому убранные офферы из потока пропадают. После ответа текущие значения копируются в опубликованные.
- Cancel удаляет неотправленные офферы и возвращает опубликованные доли и состояния.
- Remove не удаляет оффер, а переводит его в архив (`removed`, доля 0). Вернуть его можно кнопкой «Bring back».
- Fetch streams перечитывает кампанию из Keitaro, и Keitaro главнее локальных черновиков. Если оффер удалили прямо в Keitaro, у нас он становится `removed` и остаётся в архиве, а не исчезает. Потоки и кампании, удалённые в Keitaro, удаляются и у нас: при Fetch, при перезагрузке потока или при открытии списка кампаний.

## Как считаются доли

Логика в `backend/app/editor/weights.py`, пересчёт идёт после каждого изменения состава.

- Закреплённая (pinned) доля не меняется. Закрепить можно текущую долю или ввести новую в поле Share.
- То, что осталось от 100 после закреплённых, делится поровну между остальными активными офферами.
- Keitaro принимает только целые проценты, поэтому остаток от деления раздаётся по одному первым офферам: три оффера получают 34, 33 и 33.
- Убранные офферы получают 0.
- Если закреплённые доли в сумме больше 100, или все офферы закреплены, но вместе дают меньше 100, операция отклоняется с ошибкой 422 и ничего не сохраняется.

Keitaro сам не проверяет, что доли дают 100, поэтому за этим следим мы.

## Что сделал бы ещё

- Два одновременных запроса к одному потоку сейчас могут затереть друг друга, нужен `SELECT ... FOR UPDATE` на поток или номер версии.
- Меньше запросов к Keitaro при создании кампании: сейчас после создания кампания перечитывается целиком, хотя потоки уже есть в ответах на их создание.
- Загружать каталог офферов при старте, чтобы первый поиск не ждал Keitaro.
- Добавить индекс на `streams.campaign_id` и загружать потоки с офферами через `selectinload`, а не ленивыми запросами.
- На фронте блокировать все действия в потоке, пока выполняется одно из них, а не только нажатую кнопку.
- Пользователи со своим ключом Keitaro: сейчас ключ один на всё приложение.
- Фоновая синхронизация с Keitaro по расписанию, а не только по кнопке.
- E2E-тесты на Playwright для основных сценариев и Dockerfile для бэкенда и фронтенда.
